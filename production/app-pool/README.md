## 分配规则

普通用户没有访问本工具的接口；只接受可信服务器管理员操作，不接受浏览器提交任意 UserID/AgentId 作为授权。这里的用户是企业微信内部成员 UserID，不能填昵称、手机号、普通微信号或 external_userid。

应用需先在企业微信后台手动创建，完成单成员可见范围、回调和可信 IP，再准备独立的运行目录、容器和凭据。没有接入未经核实的普通自建应用批量创建接口。

状态流程：free → reserved → provisioning → assigned；失败进入 failed；管理员可停用为 disabled。数据库唯一约束和事务防止同一应用分给多人、同一成员占用多个应用。相同请求编号重复提交返回原分配；不得换人复用该编号。

预留固定 15 分钟，重复查询不续期。只有尚未开始启用的预留会到期释放。已启用、停用、失败或启用中断的应用不自动回收，不清空用户数据，也不自动更换主人。需要重新分配时先走人工注销、数据处理和核验流程；本版不提供危险的一键重置。

## 服务器命令

以下均在服务器管理员终端执行，不把 Secret 发到聊天。`reserve` 需要管理员已核对过的实际内部 UserID。示例 ID 是占位值，不会自动创建对应应用。

```sh
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py status
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py audit

# 新槽位必须已准备好、已存入其独立凭据、AI 关闭且没有用户数据。
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py register-free --agent 1000005

# 管理员创建唯一请求编号；以下两步使用同一编号。
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py reserve --owner VERIFIED_INTERNAL_USERID --request onboarding-001
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py activate --request onboarding-001

# 停用会停止整个专属容器，包括提醒和主动发送；保留数据、凭据及绑定。
sudo python3 /home/ubuntu/wecom-kf/app-pool/app_pool.py disable --agent 1000005
```

`import-assigned --agent 1000004` 用于登记已有工作中的单用户应用，重复执行不会把它改为空闲。停用后的恢复以及 failed 故障恢复需要管理员确认实际运行状态，不提供自动复用命令。

## 为下一个已创建应用生成安装包

`build_slot.py` 只生成代码，不创建企微应用、不修改当前试点或任何服务器配置。模板已同步到本次交付时的最新共享业务版本。输入新的真实 AgentId、管理员已确认的目标成员 UserID 和不存在的输出目录：

```sh
python build_slot.py --agent 1000005 --owner VERIFIED_INTERNAL_USERID --template pilot-template --output slot-1000005
```

安装包使用独立命名空间、容器、数据目录和固定成员限制；未启用时只校验回调，不把用户消息入队。安装器会验证共享源码仍与模板一致，原应用镜像仍符合预期。

将生成目录上传到服务器的私有目录后，由管理员运行其中 `install.py`。此步骤增加专属路由并启动 AI 关闭的独立容器，先备份网关配置、nginx 检查后加载，失败回滚。然后在私人终端运行该应用 `setup.py` 查看回调字段，配置企微回调/可信 IP，并通过：

```sh
sudo python3 /home/ubuntu/wecom-kf/apps/1000005/setup.py --configure-only
```

此命令私密读取并验证 Secret、存到服务器 0600 文件并重建新槽位容器，保持 AI 关闭。不要直接用 `--enable` 跳过应用池分配。之后依次 `register-free`、`reserve`、`activate`。若新槽位已经有用户数据，工具会拒绝入空闲池，不会自动删除内容。

## 部署和恢复

已部署的控制面不占额外常驻模型进程，也没有对公网暴露端口。每个聊天应用仍使用独立容器，是当前小规模试点方式；上线更多用户前需按实测内存、并发和模型费用规划容量。

管理工具需保持 root-only，不能放入公开网站或静态下载目录。备份应包含 registry.sqlite3、各应用私有配置和数据，备份也须私密存放。管理工具不读取对话正文，不复制用户数据到台账。手动修改 Docker/企微配置会造成台账漂移，应重新 audit。

卸载控制面时先停止/禁用 `xiaoyi-app-pool-recover.timer`；保留台账备份。不要删除聊天应用或任何应用数据目录。修改业务代码前单独按既有流程备份和回滚。
