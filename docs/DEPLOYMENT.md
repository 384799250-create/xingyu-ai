# 部署与恢复说明

## 本地预览

Python 3.12：在仓库根目录运行 `python tools/preview.py`，然后访问 http://127.0.0.1:18874/ai/ 。注册页展示合成的等待分配图解；账号页为匿名状态。此服务仅绑定本机地址，拒绝全部写请求，既不连接真实账号，也不调用模型、微信或支付接口。

## 后端环境

后端生产环境为 Linux、Python 3.12、Docker 和 systemd，使用 Unix Socket、fcntl、SQLite 与音视频本地库。Windows 可运行静态预览和小程序测试，生产服务应在 Linux 或隔离的 Linux 环境运行。首三个 requirements 版本来自归档当天容器；Dockerfile 是归档新增的构建入口，未执行镜像构建或生产部署验证。qrcode 声明为兼容范围。

复制 `.env.example` 到本地 `.env`，填写自己企业的回调配置与模型参数。默认 ENABLE_AI=false。Docker 构建可以使用 `docker compose -f compose.example.yaml build`；该示例将应用与门户端口仅映射到 127.0.0.1。示例不会建立完整企业管理与开通控制面；门户桥接需另行配置后才可注册开通。不要把本地示例直接替换既有生产 Compose。

## 完整企业服务

1. 为自己的域名配置 HTTPS、企业微信回调验证与合法可信 IP。把示例企业 ID 替换为自己的企业 ID，区分各企业的应用池、后台、开通与数据目录。
2. 为受限 Unix Socket 建立目录与 UID/GID 权限；门户、bridge、admin、onboarding 启动参数见各入口的 `--help` 与 production/deployment/systemd。原路径 /home/ubuntu/wecom-kf 只是结构样本。
3. 独立准备邮箱、微信小程序、短信及支付渠道配置。仅把最少配置挂到需要的服务；不要把真实配置放入 Git。仓库保留读取接口，未带任何历史凭据、商户证书、部门名单、真实二维码或订单资料。
4. 创建应用池、注册路由与生命周期管理所需的全新配置和空数据库。数据库由相关代码初始化，历史用户与金融库不属于源码包。生产原有的多租户资料不能用空库覆盖。
5. 支付渠道只在自己的测试/商户环境逐项验证，再决定启用。归档未向真实用户发送测试消息、执行真实支付或调用付费模型。
6. 小程序保持暂停状态；恢复需自行完成 AppID、API 域名、平台认证/备案及手机验收。网页设置入口在归档版本使用“我要设置”。

## 既有站点维护

对既有生产部署修改前，重新抓最新小范围源码和依赖摘要，取得所有相关企业 operation.lock，确认没有在途维护/开通/注销，备份后做定向 CAS 发布。失败时仅恢复本次源码。禁止用源码包覆盖真实身份、归属、聊天记录、钱包、余额、流水或支付配置。

历史镜像名称、systemd 服务名称与路径保留为阅读依据；本包不提供历史 Docker 镜像。当前构建入口未经过第三方微信/模型/支付的真实端到端验收。
